## 2026-10-22: WhatsApp Bot Alwaysdata Low-RAM (256MB) Optimization & Safe JID Routing
- **Issue**: Bot stopped responding to `gold` queries after a few minutes on Alwaysdata free container (256MB RAM) despite watchdog scheduled task active.
- **Root Cause**: (1) WhatsApp multi-device companion messages from phone to "Message yourself" use `@lid` or `fromMe`, which causes direct Baileys reply failures if sending directly to raw `@lid` JID; (2) Aggressive polling (3s web chat, 5s order watcher) without `.lean()` and stacked heartbeat intervals on reconnect accumulated memory beyond Alwaysdata's 256MB RAM ceiling, triggering Linux OS OOM process kills.
- **Verified Fix**: (1) Normalized `chatJid` in `isGoldQuery` directly to `923185205667@s.whatsapp.net` whenever `msg.key.fromMe || chatJid.includes('@lid') || senderPhone.length > 13` because WhatsApp Web/Mobile UI suppresses messages routed to raw `@lid` companion devices; (2) Added fallback `MONGODB_URI` string and `readyState === 1` guard in `startDailyTrendsScheduler` to prevent Mongoose buffer timeout crashes when `.env` is unhydrated on Alwaysdata; (3) Decoupled and cleaned all background intervals (`heartbeatInterval`, `orderWatcherInterval`, `webChatWatcherInterval`, `trendsSchedulerInterval`) upon socket disconnect and reduced polling frequencies to 10s/20s with `.lean()`; (4) Verified with `node --check src/worker/bot.mjs` (0 errors).
